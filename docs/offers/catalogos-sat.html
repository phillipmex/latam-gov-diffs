What you get

An invite to a private GitHub repository that carries the same nightly diff stream for the Anexo 20 catalogues. A repository, not an endpoint.

  • The diff twelve hours early. The harvest runs at 06:15 UTC and commits to your private repository in the same run; the public archive is pushed at 18:15 UTC. That is a head start on this repository's publication, not on SAT's - SAT publishes to everyone at once.
  • All 25 catalogues in one keyed table. SAT ships them as 28 sheets in a 46 MB legacy .xls, splitting c_CodigoPostal across two sheets and c_Colonia across three purely because of the old 65,536-row limit. They are re-joined, normalised into one frame and keyed on catalogo + clave + clave_2 + clave_3, so a row is comparable between releases instead of being a spreadsheet cell you have to find again.
  • Every stored version and every diff, seeded into the repository on day one: the parsed table for each archived workbook and the row-by-row comparison between neighbours.
  • An alert that comes to you. Watch the repository and GitHub emails you, or pushes to your phone, on any night that produced a change. A night with no change produces no commit and no noise.
  • A changes.json written for machines. One file to poll: the latest version pair, the added / changed / removed counts, which columns appeared and disappeared, and the path to the full diff. Compare one field with the id you last processed and stop if they match.
  • Somebody to ask. Open an issue in your own repository; first response within two business days.

What is not included

  • No hosted API. No endpoint, no key, no query language. You clone a git repository.
  • No webhooks. Nothing calls your server; GitHub notifications and changes.json are the two ways you find out.
  • No SLA. Best effort, nightly, on free hosted runners. If SAT is down that night produces nothing.
  • No exclusivity. The free archive keeps everything, twelve hours behind.
  • No custom columns and no per-customer parsing at this price, and no CFDI 3.3 - its catalogue was last republished in March 2023 and is out of scope.

What that one comparison actually caught

Twenty-one months, 46 MB of spreadsheet, 8,026 lines of diff. Read in a few minutes, and every line of it checkable against the stored workbooks:

  • c_Municipio and c_CodigoPostal Baja California created two municipalities - 006 San Quintin and 007 San Felipe, both with fecha_de_inicio_de_vigencia 2026-01-23 - and 15 new municipality rows appeared in total. Underneath them, 93 postal codes were re-pointed at a different c_municipio value. That is 93 rows a validator keyed on the old state-plus-municipality pair would now put in the wrong place, with nothing in the row count to announce it.
  • c_ObjetoImp Three new codes - 06 "Sí objeto del IVA, No traslado IVA.", 07 "No traslado del IVA, Sí desglose IEPS." and 08 "No traslado del IVA, No desglose IEPS." - with fecha_inicio_de_vigencia 2024-12-13. A five-value enumeration became an eight-value one. Anything validating ObjetoImp against a hard-coded list rejects a valid invoice until the list is updated.
  • c_ClaveProdServ Fifteen product-code descriptions were rewritten with no code change at all - the accent restored on "Combustible diésel", "Biodiésel", "Locomotoras diésel de carga" and twelve more. Nothing in the row count says so, and anything that matches a product description by text stops matching.
  • c_NumPedimentoAduana and c_PatenteAduanal 7,819 new pedimento numbers and 79 new customs-broker patents - 7,898 of the 7,917 additions. Customs is where the volume is, and a rejected pedimento number is a rejected import invoice.
  • c_TasaOCuota The IEPS quota moved from 66.5062 to 72.1605, effective 2026-01-01. It is the one removal and one of the additions - see the FAQ below, where that is explained rather than hidden.

How delivery works

  1. You pay, and give a GitHub username. A private repository is created for you and seeded with the whole catcfdi history: every stored workbook, every diff, and changes.json.
  2. GitHub sends you the collaborator invite. There is no message from us, no onboarding call, and no address to hand over.
  3. Each night at 06:15 UTC the harvest runs. SAT sends an ETag and a Last-Modified for this document, so an unchanged night is a conditional request and a 304 rather than a 46 MB download. If the workbook moved, it is parsed and the diff is committed to your repository there and then.
  4. You are notified by GitHub, or your code polls changes.json and sees a new version id.
  5. If you cancel, the invite is revoked at the end of the period already paid for. The free archive is still there, twelve hours behind, with everything in it.

The full version - the schedule, the changes.json shape, the support window, the refund policy and what is explicitly not included - is in paid.md.

Questions

Can I get this history somewhere else?

Partly, and it would be dishonest not to say so. SAT's Anexo 20 page links exactly one CFDI 4.0 workbook: the current one. Older dated files such as catCFDI_V_4_20241204.xls are still live at their own URLs and still return the bytes SAT served then - they are simply linked from nowhere, so a URL nobody wrote down is effectively gone. Nothing here is hidden from you and nothing is exclusive. What is not published anywhere, by SAT or by anyone else, is the comparison: which rows moved, in which catalogue, and when. That is what you are paying for.

Who is this for?

Developers who maintain CFDI 4.0 validation or catalogue tables - a PAC integration, an ERP's fiscal module, an invoicing SaaS, or the lookup tables behind any of them. If a copy of c_ClaveProdServ, c_CodigoPostal, c_ObjetoImp or c_RegimenFiscal lives in your database or in your test fixtures, this feed tells you what to reconcile before a timbrado starts coming back rejected rather than after.

What actually breaks when a catalogue moves?

Four things, in rising order of how long they take to find. A new code appears and your validator rejects an invoice that SAT would have accepted - the c_ObjetoImp case above. A code is removed or a rate is superseded and you keep stamping the old one. A row's non-key values are rewritten, like the 93 postal codes that changed municipality, so your data is still shaped correctly and is now wrong. And the quietest one: a description is rewritten with no code change, so anything matching on text rather than on the key stops matching, with nothing in the row count to tell you.

Is the diff perfect? What are its known limits?

One catalogue is keyed imperfectly and it is written down rather than papered over. c_TasaOCuota is not a code table - its rows are tax rates, and the c_TasaOCuota column holds only the lower bound of a range and is empty on the 16 fixed-rate rows. There is no stable identifier in the sheet, so it is keyed on (rango_o_fijo, impuesto, valor_maximo), and the honest cost is that a rate change reads as one removal plus one addition instead of one change: the IEPS quota going from 66.5062 to 72.1605 is the single -1 and one of the +1s in the recorded revision. Both records carry the full row, so nothing is lost - it just needs reading as a pair. Separately, one row of c_TipoDeComprobante carries no code at all (it holds only the Valor maximo limits) and is dropped; it is the only such row in the workbook.

What happens if SAT changes the file format?

That night's harvest produces nothing rather than producing something wrong, and the issue tracker says so. The parser already survives a fair amount - it finds each sheet's header by content rather than by row number, because SAT puts it on row 4 or row 5 depending on how many blank spacers sit under the title, and four sheets write a second header line under the first. If a change goes past that, the parser is fixed as fast as it can be fixed and the workbook is re-parsed from the stored copy, so no revision is lost. There is no SLA and no credit: the honest description is best effort, nightly.

What happens when I cancel?

Access runs to the end of the period you have paid for, then the collaborator invite is revoked and the private repository is archived. Nothing is clawed back: anything you cloned stays cloned, and every diff you were sent is still yours. The public archive keeps publishing, free, twelve hours behind.

Why should I pay when the archive is free?

Often you should not, and the free tier is genuinely the right answer for most readers. Three things are behind the price and nothing else: the diff twelve hours earlier, an alert that reaches you instead of you remembering to check a page that shows only the current file, and somebody to ask when a row makes no sense. If none of those three is worth $39 a month, use the free viewer - it is not a trial and it is not reduced.
